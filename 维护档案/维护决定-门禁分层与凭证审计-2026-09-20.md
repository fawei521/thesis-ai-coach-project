# 维护决定 · 2026-09-20 · 门禁按改动面分层 ＋ 门禁凭证审计（让偷懒留痕）

> 记账类档案（git 追踪、`export-ignore` 不进发布包）。包内 `CHANGELOG.md` 的“维护决定（不发版）”只留一条指针，正文在这里——这样既不撞它的行数上限，也不让决定文本被删掉。

- **2026-09-20｜门禁凭证审计：让"偷懒"留痕（不发版）**：下一条的门禁分层带来一个新漏洞——**沉默式跳闸**：动了该跑全量的
  东西、只跑秒级就宣称通过，而这件事本身不留痕迹，唯一防线就退化成"人在旁边盯着"。同时按维护者指定的下限
  补一条：**一个版本收尾至少一次全量留痕**（已写进 `DEVELOPMENT.md` 阶段 G 与发布前清单）。
  机制：`python tests/smoke_check.py --full` 末行打印 `[门禁凭证] head=<跑那一刻的HEAD短号> smoke=9/9 full=N/N`，
  **原样贴进 commit 说明**；`case_21.py` 审计锚点之后每笔动了 L1 的 commit 有没有这行、`head=` 对不对得上父提交、
  `full=` 是否零失败。三点设计取舍：① 凭证**只活在 commit message 里**，不另建日志文件（建了就是又一份会漂的副本）；
  ② L1 边界**不另抄名单**，现读阶段 T 那张表第二列含 `**全量**` 的格子里的反引号路径（实测解析出 15 条）；
  ③ 锚点用 `git log -S 门禁凭证` 自动定位，**不写死 hash、不给历史补凭证**。
  两把防地滑自测（植入必须抓到、合规必须放过）＋两种伪造都要判红，本批新增 4 条断言。
  总项数一律看 `python tests/smoke_check.py --full` 末行，不在这里抄——
  上一版之后 P8/P15 两笔未记账的改动也在涨，抄一个数就是埋一个会过期的数。
  **能力边界如实写**：这**防不住铁了心伪造**（手填正确短号做得到）；它把"忘记/侥幸"的成本抬到"主动伪造且痕迹永久
  留在 git log"，并让任何一轮后续回归都能事后追责——**它不替代 P2/P13 真人走查，也不等于此规则已生效。**

- **2026-09-20｜门禁改成按改动面分层（不发版）**：维护者反映"每完成一个小改动都跑全量太费时间"。实测后两件事一起修：
  ① **时长说法是假的**：全量实测 **69.7 秒**，而 `AGENTS.md`／`DEVELOPMENT.md`／`README.md` 三处写着
     "约 3-5 分钟"——漂了 3 倍且往贵了漂，**把门禁说得比实际贵本身就在劝人不跑**。三处已改，
     并按测试90 的同一原则**不再在文档抄秒数与项数**（耗时只在阶段 T 的表里写一次、标日期当量级看）。
  ② **该修的是节奏**：新增 `tests/smoke_check.py`——把现成 8 个检查器按序调一遍，**5.6 秒 / 9 项**，
     它是聚合器、不复制任何判据逻辑（逻辑抄进来就又造一个会漂的副本）。分层线写在
     `DEVELOPMENT.md` 阶段 T 的"跑哪一道闸"表：**按改动面判**（碰 `.py`／菜单开关／导出口径／
     学生侧规则文档／任何一句带事实的话 → 全量；纯记账文字 → smoke，但本会话收尾补一次全量）。
  新守卫四条（`case_02.py`）：smoke 全绿、smoke **<20 秒预算**（防便宜层长胖后规则名存实亡）、
  定闸表只写一处、入口文档必须指向它。full_e2e 776→**780**。
  **如实记两件没证的**：① "AI 会不会偷懒只跑 smoke 就宣称通过"——**已由上面的凭证审计管住一半**
  （动了 L1 却不跑全量＝事后判红），但"跑过了"不等于"做对了"；本条没进 `behavior-self-test.md`
  （那文件的范围是学生引导流程），真实对话质量仍要等 P2/P13 真人走查；
  ② 全量里那步真打英文文献 API、超时上限 90 秒，断网时整轮约涨到 160 秒——**按维护者决定不动它**，
  只把时长说法改准。各文件的行数余量看 `python tests/size_ratchet.py` 的 WARN 行，别在这里抄数字。
