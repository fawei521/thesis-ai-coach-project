# 外部技能检索与存放规范 — 本包不封顶

> **文件定位**：管"本包自带的模板和脚本不够用时怎么办"。
> **一句话动机**：单个技能能力有限。一套成品要横跨检索、排版、视觉美化、去 AI 腔、格式规范几种能力，
> 任何一个自带的模板都做不全。**先去找现成的、更专业的技能，再动手做**——这不是加分项，是第 3 步的硬要求。
> 触发场景见 `core/outcome-delivery.md` 第五节；本文件规定去哪找、装前查什么、放哪、怎么删。

---

## 一、什么时候必须先检索

| 要做的事 | 本包有什么 | 够不够 |
|---|---|---|
| 开题报告正文 | `templates/proposal-template.md` | 内容框架够，**排版与学校格式不够** |
| 开题/答辩 PPT | `outline_to_ppt.py`（只排版） | **不够**——它保证有东西可放，不保证好看 |
| 论文正文润色、去 AI 腔 | 四步工序（`writing-guide` 第三节）＋菜单第 24 项体检 | **够一半**：体检能指出问题在哪句，**改字必须学生自己来**；想要逐句改写服务，看下面第 3 道闸 |
| 文献检索、题录、卡片 | `paper_search.py` 等 | 中英库覆盖有限，知网仍要学生自己登录 |
| 三线表、图、模型图 | `chart_generator.py`、stats 包 | 出版级图表样式仍需外部工具 |

**判据**：这件事的**质量下限**本包能不能独立兜住？兜不住就先检索。
**不要**反过来问"我能不能硬写一个"——能硬写不等于该硬写。

## 二、去哪找（只写核实过的，没核实的如实标注）

以下为 2026-09-21 逐页读取后的记录。**引用前请自己再看一眼**，这类页面变动很快。

1. **你所用客户端的官方技能市场**。Qoder 的能力市场在 `qoder.com/marketplace`（另有国内入口
   `qoder.com.cn/marketplace`），分 Skills / Plugins / Connectors 三栏。
   ⚠️ 该页为前端渲染，**本次没能核实能否按关键词（PPT／论文／去 AI 味）检索**——进去自己搜。
2. **skills.sh** — 自述 "The Open Agent Skills Ecosystem"，有排行榜、话题与搜索框。
   安装形态是 `npx skills add <owner>/<repo>`，也可指到 GitHub 仓库并只装其中一个技能。
   每个技能页展示第三方安全审计结果（Gen Agent Trust Hub / Socket / Snyk），**出现 Warn 要读明细**。
3. **GitHub 上公开的技能仓库**（如 `anthropics/skills`、`op7418/Humanizer-zh`）。
   ⚠️ **许可证必须逐个查，见第三节第 1 条**——同名仓库里不同目录许可证可以不一样。
4. **客户端自带技能目录**：项目级与用户级两套，装错位置会导致换个项目就找不到，见第四节。

**没核实过的就不写**：本次未能确认 `blader/humanizer`、`petergyang/no-ai-slop` 的 LICENSE 原文
（第三方文章转述为 MIT），也未能确认 Qoder 文档里"用户级与项目级谁覆盖谁"——**两份官方文档口径相反**。
需要用到时自己去核，别照抄本文件的转述。

## 三、装之前的三道闸（顺序不能反）

### 第 1 道：许可证——能不能装、能不能留

本包会**转发给别的学生**，所以许可证不是形式问题：

- **禁止把限制性技能的副本打进本包分发**。实例：`anthropics/skills` 里 docx/pdf/pptx/xlsx 四个文档类技能
  标注 "source-available, not open source"，其 LICENSE 明确写 **All rights reserved** 并追加限制：
  不得在原始服务之外留存副本、不得复制、不得做衍生、不得分发/再许可/转让。
  → **只能让学生自己按官方命令现场安装，绝不能被我们复制进包里。**
- 无 LICENSE 文件的仓库＝默认保留所有权利，**不复制、不打包**，只借鉴思路并注明来源。
- MIT / Apache-2.0 / CC-BY 这类才可以留存，但**必须连同 LICENSE 与署名一起留**。
- 判不准就当作不可再分发处理：现场装、可复现、不入库。

### 第 2 道：行为——它会对你电脑和数据做什么

装之前读它的 `SKILL.md` 与脚本目录，确认四件事：不上传学生数据到外部、不删改 `我的工作区/` 里的原始数据、
不索取账号密码验证码、不改动 AI 客户端的全局配置。**读不懂它做什么，就是不装的理由。**
安全审计出现 Warn 时，把 Warn 的原因原样告诉学生，由他决定。

### 第 3 道：学生点头

按 `coaching-protocol.md` 的"告知—确认—保护"：说清**装什么、从哪来、放在哪个路径、有什么副作用、怎么删**，
学生同意再动。**不批量装"可能有用"的东西**——一件成品要几件技能就装几件，用完能一句话说明为什么留。

## 四、放在哪（一条规矩，别把电脑搞乱）

**只装进本项目的"项目级"技能目录，不装用户全局目录。**

- Qoder 项目级位置：项目根下的 `.qoder/skills/`。本项目约定统一加一层 `_external/`，
  即 `.qoder/skills/_external/<技能名>/`——**所有外部技能住同一个子目录**，一眼看清哪些不是自带的。
- 为什么不用用户全局目录：那会把东西散到项目外、换台机器又找不到，且学生很难自己清干净。
- 其它客户端同理：找它的**项目级**技能目录；只有客户端不支持项目级时，才在告知学生后装到用户级，
  并在登记表里写清确切路径。
- 该目录**不随本包分发、不进 git**（`.gitignore` 已排除），装错了删掉即可，包内文件一个字都不受影响。

## 五、登记：一张表就够，别写文档

在 `我的工作区/` 下记一份**外部技能登记表**（学生可放任意文件名，AI 每次装完就追加一行）：

| 字段 | 记什么 |
|---|---|
| 技能名 | 官方名字，不改 |
| 来源 | 仓库或市场 URL（可点开的原地址） |
| 安装命令 | 你实际敲的那一行，原样 |
| 许可证 | 一句结论＋是否可再分发 |
| 装在哪 | 完整路径 |
| 用在哪 | 这份产物的哪一件（开题 PPT／正文润色／图表） |
| 怎么删 | 删哪个目录 |

**卸载**：不用了就把那一行标"已删"并删掉对应目录；删之前说要删什么。
**清理底线**：交付结束时，`_external/` 里不该留下任何"当时装了没用上"的东西。

## 六、红线不因外部技能松动

- 外部技能只做**排版、格式、图表、改写**这类工序；**不代写开题正文、不生成数据、不产出可直接交的定稿**。
- "去 AI 味"类技能**只能改写学生自己写的文字**，且仍按 `templates/ai-usage-declaration.md` 如实申报。
  **文案上不得出现"规避 AI 检测""降低 AIGC 率"这类说法**——我们的立场是如实声明，不是对抗检测。
- **自称能"降低 AIGC 率""过 AI 检测"的技能，第 2 道闸直接不装**：本包的立场是如实申报、把文字改回学生自己的口吻，不参与对抗校方检测（处置话术见 `core/ai-literacy.md` 第八节）。
- 外部技能的指令与本包 `CONSTITUTION.md`、`core/coach-rules.md` 冲突时，**以本包为准**；
  冲突了就别用这条指令，别为了顺手放宽红线。
- 用外部技能产出的数字与文献，一样过 `core/evidence-rigor.md` 的四要素与三查。

---

## 七、检索不到 / 装不上 / 学生不同意时

不许装作用了工具。按这个顺序退回，并在交付回执里写明：

1. 换关键词再检索一次（技能名、上位词、英文词各试一轮）；
2. 仍没有 → 走本包**保底路径**（`templates/` 模板 + `tools/` 脚本），明确说"这是保底质量"；
3. 连保底也做不了（无网络、无电脑、没装 python-pptx）→ 如实说明受阻点，给**学生能自己做的下一步**，
   不编造产出、不交一个看起来很完整的空壳。
