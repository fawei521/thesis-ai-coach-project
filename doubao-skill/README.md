# doubao-skill —— 独立分发的轻量版（手机可用）

> 本目录是 **thesis-ai-coach 轻量版的权威源文件**，随完整版项目一起版本化管理，**但可以单独拿走使用**。
> - **完整版项目**（START.md + tools/ + workflows/ + psychology/）面向**电脑**上"把整个文件夹交给 AI"的学生，多的是脚本与图表能力；
> - **本 Skill** 面向**手机**上"装个技能/发一个文件就被引导"的学生，**不含 Python 脚本、不需要电脑**；
>   引导规则、阶段流程、学术口径与完整版一致，手机走到哪一步、换到电脑可以从那一步接着走。
>
> ⚠️ **能力边界**：手机能做大部分，但有两处必须换电脑——① 阶段 7 的预处理/清洗/反向计分/量表总分；② 阶段 8 的全部统计分析（JASP/SPSS/PROCESS 都是电脑软件）；排版、查重、AI 检测、PPT 定稿也建议回电脑。技能会在**阶段 6 开题通过后**提醒并带学生填设备交接单，**不会假装能算**。完整边界见 `references/mobile-guide.md`。

## 目录与安装

```
doubao-skill/
├── SKILL.md              入口（frontmatter + 触发边界 + 启动协议 + 手机能力边界）
├── CHANGELOG.md          Skill 独立版本历史
├── README.md             本文件（维护者读，不对学生朗读）
├── validate.py           结构自检（纯标准库，见下）
├── build_mobile_single.py 合并单文件生成器（维护者用，见下）
├── .skillignore
├── personalities/        default=默认自然语气（不套人设）；其余 3 个为可选语气（默认不加载）
├── stages/               12 阶段引导（stage-0 … stage-11），统一"准入→流程→准出"结构
├── references/           引导协议、鼓励系统、阶段速查、手机说明、常识资料、维护者自测
└── templates/            进度文件模板（阶段 0 发给学生另存）
```

### 三种启用方式（按平台选）

1. **手机 · 豆包 App**：更新到最新版 → 在「工作任务 / 技能」入口新建或导入本目录内容，
   保持 `SKILL.md` 在根。**入口措辞随版本变化，以你手机上实际看到的为准 `[需核实]`。**
2. **手机 · 通用（保底，一定能用）**：把**合并单文件** `thesis-ai-coach-手机版.md` 作为附件发给 AI，
   说"请按这个文件当陪我做毕业论文的 AI 助手（不用当老师，就当一个好用的学习搭档）"。该文件自带全部规则，不需要再传别的文件。
3. **电脑 · 豆包桌面版**：把本目录**内容**复制到
   `…/.doubao/agent_mode/workspace/.user_skills/thesis-ai-coach/`，保持 SKILL.md 位于该目录根部。

## 合并单文件（手机保底路径）

有些平台不收文件夹、或一次只让发一个附件。用生成器把整个 Skill 合并成一个 md：

```
python build_mobile_single.py                     # 输出到本目录 thesis-ai-coach-手机版.md
python doubao-skill/build_mobile_single.py        # 从仓库根跑也一样写在 doubao-skill/ 里
python build_mobile_single.py --out 路径.md        # 只要产物放到别处（相对路径按当前目录解析）
python build_mobile_single.py --check             # 校验已生成的合并版是否与源文件同步
```

- **逐文件原样拼接，不改写任何规则文字**（避免"生成版与源版不一致"）；
- 带**内容指纹**，源文件改过而忘记重新生成时 `--check` 会报不同步；
- 默认输出路径与 `validate.py` 检查的是同一份，且这份产物**随包分发**（它是手机侧唯一"一定能用"的交付物，
  而发布包由 `git archive` 生成、只装 git 跟踪的文件——所以它必须入库，不能当构建产物排除；`.skillignore` 仍把它挡在技能导入之外）；
- **改完任何源文件都要重新生成一次**：`python build_mobile_single.py`，否则 `validate.py` 判不同步。

## 设计原则（改动时必须遵守）

1. **与完整版口径一致**：样本量（简单中介 ≥200、链式建议 ≥300）、五指标清洗、Harman <40%、Bootstrap 5000/95%CI、答辩高频问题 24 问、12356 热线、未成年人 assent 等硬口径以完整版最新版为准；两边改动要互相追平。**这条现在有机器盯**：`python tests/skill_sync_check.py`（完整版一侧的口径表 + 版本自述单一源），改任何一条硬口径都要两侧同改并重跑。
2. **轻量版不假装拥有工具**：没有脚本就明说没有，需要自动化时指引完整版，禁止编造运行结果。
3. **手机能力边界要如实**：阶段 7 预处理与阶段 8 统计必须回电脑，不教手机硬算、不凭口述数字估结果；阶段 6 开题通过后主动提醒并带填设备交接单。
4. **默认自然语气**：不套人设；三种语气仅在学生主动选择时加载。
5. **鼓励系统默认打开、可关闭**：标准/精简/关闭三档，夸具体行为不夸天赋，P0 不用鼓励包装。
6. **不确定就标 `[需核实]`**：量表数字、文献、学校规定不得凭记忆给确定值。
7. **阶段文件统一结构**：阶段卡 → 准入检查 → 产出物 → 分步引导（助手动作/学生任务/检查点/鼓励时点）→ 卡点 → 红线 → 三闸准出。

## 自检与发布

每次改动后：

```
python validate.py                      # 结构/口径自检（本目录内），退出码 0 才算通过
python build_mobile_single.py --check    # 合并单文件是否与源同步
python tests/skill_sync_check.py         # 在仓库根跑：硬口径与完整版两侧一致、版本自述单一源
```

退出码 0 才算通过（检查 frontmatter、必备文件、阶段编号连续性、三闸 checkbox、内部链接、
鼓励开关、安全口径、手机能力边界、占位符残留、**手机合并单文件在位且与源同步**）。

发布流程：
1. 跑上面三条（缺合并单文件时 `validate.py` 直接判红，按它的提示生成即可）；
2. 改过任何源文件就重新生成合并单文件 `python build_mobile_single.py`，并把这份产物一起 `git add`
   ——它随包分发，而发布包由 `git archive` 生成、只装 git 跟踪的文件；
3. 手机端：把**合并单文件**给学生（最稳）；桌面端：把本目录内容同步到 `.user_skills/thesis-ai-coach/`；
4. 在本文件同级 CHANGELOG.md 追加 Skill 版本条目（Skill 独立语义化版本，并注明"对应完整版 vX.Y.Z"）——
   这是全包唯一的版本自述处：SKILL.md 顶行只写 Skill 自己的版本号，README 不再抄一份清单。
