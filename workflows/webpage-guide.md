# 学生自己做网页 · 引导手册

> 读这个文件的时机：学生说"我想做个网页""帮我把文献整理成网页""我的统计结果能不能做成看板"
> "我之前做的网页在哪 / 帮我打开看看"，或你在阶段 2/3（文献）、阶段 8（数据分析）判断做网页比
> Markdown 表格更合适时。
>
> **一句话定位**：网页是学生**给自己用**的整理与展示工具，帮助学生理清和看懂自己的东西；
> **它不是论文成果，也不能替代学生自己的分析**。
>
> **带教约定**：本文件只提供本主题的专业步骤；每轮对话仍按 `core/coaching-protocol.md` 走引导循环、反馈三段式与 P0/P1/P2 分级，鼓励按 `core/encouragement-guide.md`（默认标准档，学生说"关闭鼓励"即关）；属于正式阶段的，收尾过 `core/coach-rules.md` 第十一节三道闸。

## 一、先判断：该不该做网页

### 适合做的信号
- 资料**条目多、需要反复检索/筛选**（几十篇文献、上百个术语、几十道量表题）
- 内容**有结构关系**（研究模型、变量路径、流程步骤），文字表达不清、图更清楚
- 结果**要反复给不同人看**（答辩前给导师看、给同学看、手机上自己看）
- 学生自己**主动想做一个**（有学习动力时做，效果最好）

### 不该做、要先劝住的
- 学生以为"做了网页就算成果"、想把网页写进论文 → **明确纠正**：论文只写方法与结果，网页是辅助工具
- 学生还没读文献，就想先做文献网页 → 先读文献，内容都没有，做了也是空壳
- 学生想用网页"凑工作量" → 直说没用，把时间放到数据和写作上
- 学生想做一个需要服务器/数据库/登录的网站 → **超出本项目范围**，劝回单文件网页

> **判断标准**：做完之后，学生能更快地找到/看懂自己的东西吗？不能，就别做。

## 二、五类网页（对应论文阶段）

| 类型 | 用在哪一阶段 | 解决什么 | 参考范例 |
|---|---|---|---|
| **① 文献笔记网页** | 阶段 2–3（文献检索与精读） | 几十上百篇文献记在 Word/Excel 里找不到、筛不动；做成可按关键词搜、按分类筛、给重点打星 | `templates/网页范例/01-文献笔记网页/index.html` |
| **② 数据分析结果看板** | 阶段 8（数据分析）后 | `auto_stats.py` 输出的三线表/相关热图/中介结果散在多个 CSV 里，学生看不懂整体；整理成一页可对照 | 无范例，按第三部分从零带 |
| **③ 研究流程 / 模型可视化** | 阶段 1、6（选题与开题） | 变量关系、研究步骤说不清；用纯 HTML/CSS 画出来，开题和答辩都能讲 | `templates/网页范例/03-研究流程图/research-flow.html` |
| **④ 量表与问卷速查页** | 阶段 4–5（量表选择与问卷设计） | 多个量表的题数/维度/信度/计分混在一起容易错；做成对比速查 | 可参考 `02-术语词典网页` 的分类卡片结构 |
| **⑤ 论文进度看板** | 全程 | `我的工作区/我的论文进度.md` 是纯文本，做成可勾选的看板更直观 | 可用 `templates/progress-template.md` 的内容转写 |

## 三、硬规矩（不可违反）

1. **单文件、自包含**
   一个 `.html` 文件，CSS 和 JS 全部写在文件里，数据用一个 JS 数组常量放在顶部。
   学生双击就能打开，不装任何东西。**不要生成多个文件、不要用构建工具。**

2. **不引用外部资源**
   不写 `<script src="https://cdn...">`、不写外部字体/图标 CDN。
   字体用系统字体栈：`'Noto Sans SC','PingFang SC','Microsoft YaHei',sans-serif`。
   *理由*：外链一旦失效或断网，学生看到的就是白屏或错版，而学生往往不知道是网络问题。
   （`templates/网页范例/02` 和 `03` 里各有一个外链字体，是真实项目里的反例，见范例 README 的说明。）

3. **不放个人隐私**
   姓名、手机号、身份证号、学号、可识别到个人的照片，一律不进网页。
   问卷原始数据尤其不能直接嵌进网页（含 IP、作答时间等）。要举例就用**编造的示意数据**并标明"示意"。

4. **内容必须真实、可追溯**
   文献条目必须来自学生**自己检索并读过**的文献；术语释义要能说出处；统计数字必须来自学生自己跑出来的结果。
   **绝不替学生编文献、编数据、编结论填进网页。**

5. **网页不是论文成果**
   正文、结果、讨论都写在论文里。网页只是学生自己的整理工具。
   学生要写进论文的，只有网页**帮助他理清**的那些内容，且必须是学生自己写的。

6. **不联网、不上传、不改学生数据**
   生成网页只是写一个文件到 `我的工作区/04-网页/`。
   预览用本项目的本地服务器（只读），**不做任何上传**。

## 四、引导流程（一步一步来）

> 沿用 `core/coach-rules.md` 第十节的"告知-确认-保护"：**先说要做什么、等学生同意，再动手。**

### 第 1 步：问清用途（不要跳）

一次问一个，别一口气问完：

- "你想用这个网页解决什么问题？"（找不到文献？看不懂结果？答辩讲不清？）
- "内容你现在有多少了？"（有清单/有结果文件/还没有，只是想做）
- "主要在哪看？电脑还是手机？"（决定布局与字号）

**如果学生答不上来"解决什么问题"，先回到上一节的"不该做"。**

### 第 2 步：确认类型与数据来源

对照第二部分的表，告诉学生建议做哪类、为什么。
明确**数据从哪来**：
- 文献网页 → 学生的文献表（`我的工作区/01-文献PDF/`）或已经整理好的笔记
- 数据看板 → `我的工作区/03-分析结果/` 里 `auto_stats.py` 导出的 CSV
- 流程图 → 学生口述的变量关系（**由学生确认，你不要自己编变量关系**）

### 第 3 步：看一眼范例（可选但有效）

告诉学生可以双击打开 `templates/网页范例/` 里的三个网页看效果，问"想要这种感觉吗"。

> ⚠️ 必须同时说清：**范例只能学做法，里面的文献和术语内容不要抄。**

### 第 4 步：生成第一版（先做小）

- 先用**少量真实内容**（比如 5 篇文献、3 个结果）做出一版能打开的页面，让学生看结构对不对
- 确认后再补全
- 生成后**立刻让学生打开看**，不要一次写完 100 条才发现结构不对

### 第 5 步：本地预览

告诉学生两种方式（见第六部分）。**预览时必须让学生自己看到页面**，不能只说"已经生成好了"。

### 第 6 步：迭代与留痕

- 每轮改动问学生"哪里不对/还想加什么"
- 网页文件路径记进进度卡（`我的工作区/我的论文进度.md`）
- 提醒学生：这个文件是他的，可以随时自己改；换电脑记得整个文件夹带走

### 第 7 步：过检查闸

按 `core/coach-rules.md` 第十一节，用下面的清单核对后再算完成。

## 五、生成网页时你要做到

- **数据与界面分离**：内容放顶部一个 `const DATA = [...]`，界面代码只读它。学生要加内容只改数组。
- **中文优先**：`<meta charset="UTF-8">` 必须有；字体栈带中文字体。
- **移动端可用**：加 `<meta name="viewport" content="width=device-width, initial-scale=1.0">`。
- **搜索与筛选**（条目多时必备）：一个搜索框 + 分类按钮，纯 JS 实现。
- **不引入框架**：不用 React/Vue/Tailwind CDN，用原生 HTML/CSS/JS。
- **代码可读**：加中文注释，学生以后自己改得动；这也符合本项目"学生必须理解自己在做什么"的原则。
- **醒目处写清数据来源与日期**：例如"数据来源：本人 2026-09 知网检索，共 47 篇；统计结果由 auto_stats.py 于 2026-10-01 导出"。

## 六、预览方式

**给学生（推荐，不用记命令）**：双击项目根目录「启动工具箱.bat」→ 选第 9 项「预览我做的网页」。

**命令行**：

```bash
python tools/webpage_preview.py            # 预览 我的工作区/04-网页/
python tools/webpage_preview.py --list     # 只列出有哪些网页
python tools/webpage_preview.py 某目录      # 预览指定目录
python tools/webpage_preview.py --lan      # 手机也可看（同一 WiFi），用完记得关
```

预览器是**只读**的：不能上传、不能改文件、不能越出指定目录。默认只绑本机（`127.0.0.1`）。

> 其实单文件网页**双击就能用**，预览器主要用于：目录里有多个网页要挑、想让手机看、或者想确认页面在 http 环境下也正常。

## 七、常见坑（提前告诉学生）

| 坑 | 现象 | 怎么办 |
|---|---|---|
| 用记事本改完保存成 `.txt` | 双击打开是代码 | 用"另存为"选"所有文件"，文件名写 `xxx.html` |
| 用了外链字体/图标 | 断网就错版或白屏 | 改成系统字体栈，见硬规矩第 2 条 |
| 内容直接写在 HTML 标签里 | 想加一条得改几十处 | 统一放进顶部数组常量 |
| 中文乱码 | 页面全是方块/问号 | 确认有 `<meta charset="UTF-8">`，文件本身以 UTF-8 保存 |
| 把问卷原始数据粘进网页 | 泄露隐私，且文件巨大卡顿 | 只放汇总结果，不放逐人原始作答 |
| 直接抄范例的文献条目 | 学术不端风险 | 内容必须来自自己检索核实的文献 |
| 改了网页、刷新却还是旧内容 | 浏览器缓存，带离线缓存（service-worker）的范例在 http 预览下尤易出现；双击 file:// 打开一般无此问题 | 先按 Ctrl+F5 强制刷新；仍不生效，让 AI 把 `service-worker.js` 里的 `CACHE_NAME` 版本号 +1（如 v1 改 v2）后再刷新 |

## 八、完成检查闸（三闸）

**闸 1 动机闸**
- 学生能说清这个网页解决他什么问题吗？说不清 → 回去想。

**闸 2 质量闸**
- [ ] 单文件、双击能打开、不依赖外网
- [ ] 内容全部真实、可追溯；没有编造的文献/数据
- [ ] 没有个人隐私信息
- [ ] 中文不乱码、手机上能看
- [ ] 学生自己打开看过，并说得出哪里是他的内容、哪里是界面
- [ ] 明确告诉过学生：**这不是论文成果**，论文仍需自己写

**闸 3 留痕闸**
- [ ] 网页文件在 `我的工作区/04-网页/`
- [ ] 文件路径记进进度卡
- [ ] 数据来源与生成日期写在了页面上

三闸都过，才说"这个网页做好了"。
